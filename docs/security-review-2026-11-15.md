# Security review and fixes — 2026-11-15

The review covered the HTTP dispatcher, configuration and catalog validation, filesystem boundaries, ZIP extraction, release activation, process shutdown, browser management UI, runtime dependencies, and the installed deployment's app integrations. Reproductions used synthetic secrets and temporary storage. Existing private answers were not modified by testing.

| Finding | Change | Regression evidence |
| --- | --- | --- |
| A reachable client could publish, overwrite, or shut down apps without authentication. | Private administrator key, short-lived bearer sessions, authenticated publishing and all mutations. | Unauthenticated commands, forged cookies, expired/revoked sessions, browser sign-in and sign-out tests. |
| Hosted scripts shared an origin with administration and other apps, exposing browser storage and same-origin files. | Fresh administrator origin, one persistent origin per hosted app, own-app file routing, explicit asset grants, no management APIs on app origins. | Real-browser cross-port storage, file, and management attacks fail; origin reuse is rejected. |
| Host-based checks did not establish an exact browser-origin boundary. | Exact scheme/host/port checks, rejection of same-site cross-origin subresources, no CORS, browser mutation header. | Wrong schemes/ports, legacy hosts, cross-site metadata, preflights, raw malformed HTTP. |
| Parent symlinks and macOS case aliases could make private storage overlap served files despite lexical path checks. | Canonical filesystem paths and overlap checks at startup and reload. | Alias, reversed nesting, private file, symlink, traversal, and fail-closed reload tests. |
| Unlimited retained releases could exhaust disk space. | Storage quota, free-space reserve, bounded release retention, active-release preservation. | Repeated publication, low-space rejection before upload, worker timeout, interrupted upload cleanup. |
| Runtime and locked dependencies needed security updates. | Node 24.22.3 minimum; updated Multer, body-parser, and qs. | Clean lockfile install and zero known vulnerabilities reported by npm audit at review time. Advisory presence did not establish that every affected function was reachable. |

The automated suite contains 46 passing tests with no skips on the reviewed macOS installation, including 35 separately constructed malicious archives, malformed multipart requests, duplicate HTTP headers, decompression bounds, CRC corruption, worker deadlines, and the existing publishing/lifecycle/order tests. Chromium checks exercise real separate HTTPS origins, administrator sessions, and browser-storage migration. CI installs its browser and fails if browser tests cannot run.

Compatibility checks against a separate copy of the installed content covered 20 active hosted sites and eight stopped sites. Browser checks exercised school datasets and persisted selections, photo assets/viewing/saved decisions, résumé load/edit/autosave/reload against a synthetic backend, finance detail tabs, clinic location navigation, and the static guide. Photo asset URLs were migrated into an explicitly authorized dependency group. Directory visibility and ordering were preserved. The optional `/_vercel/insights/script.js` requests already returned 404 before this change; they do not affect those app functions.

The boundaries are documented in [SECURITY.md](../SECURITY.md). Tailnet reachability still permits reading app content; administrator authentication controls changes. Different ports isolate browser origins but not arbitrary cookie-authenticated external services. External linked applications retain their own security model. Saved localStorage migrates when the user visits the old app link in the browser that owns it; temporary session state is not transferred. Testing cannot prove the absence of all vulnerabilities or establish that earlier shared-origin data was never accessed.
